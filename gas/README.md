# GAS (Google Apps Script) — 작업타이머 시트 API

## 정본은 Apps Script 편집기다
이 폴더의 파일은 **편집기에 넣을 것 / 넣은 것의 사본**이다.
수정할 일이 생기면 **반드시 편집기의 현재 코드를 먼저 받아서** 시작할 것 —
옛 베이스에서 재작성해 기능이 유실된 사고가 있었다(v47/v48).

| 파일 | 내용 |
|---|---|
| `AppsScript-v54.gs` | 편집기에 통째로 붙여넣을 완성본 |
| `v54-수정지침.md` | 4곳만 손으로 고치고 싶을 때의 지침 (완성본과 결과 동일) |

## v54 가 v53 에서 바꾼 것 (6곳)
1. **【버그】`READ_ROWS` 미설정으로 150행 아래가 사라짐** — `ensureMembers` 가 팀원 캐시(60초)에
   적중하면 `READ_ROWS` 를 안 정하고 반환해, `doRead` 가 기본값 150행으로 읽었다.
   시트가 150행을 넘는 순간 그 아래 작업이 **캐시 살아있는 동안만 간헐적으로** 사라진다.
   (2026-08-27 실측 시 마지막 항목 93행 — 아직 안전했지만 여유가 얼마 없었다)
2. `ensureMembers` 와 `doRead` 의 그리드 **중복 읽기 제거** (`readGrid`, 요청당 1회)
3. `doRead` 응답 **20초 캐시**
4. **쓰기(insert 포함) 전후로 캐시 무효화** — 3번을 넣으면 필수
5·6. 헤더 버전 표기 · insert 경로 무효화

## 왜 캐시인가 (2026-08-27 실측)
| `action=read` | 소요 |
|---|---|
| 충분히 쉰 뒤 1회 | 3.4초 |
| 연속 1→2→3회차 | 8.9 → 27.2 → **70.9초(실패)** |
| 연속 5회차 | 19.9초 |

응답은 33KB뿐이다. **전송량이 아니라 GAS 실행이 줄을 선다.**
`action=members`(시트 거의 안 읽음)도 1.8~3.5초라, 그게 GAS 왕복의 기본 비용이다.
→ 실행 시간을 줄이는 것보다 **호출당 실행량을 없애는 것**이 효과가 크다.

## 배포 방법
**배포 → 배포 관리 → 편집(연필) → 버전 "새 버전" → 배포**

⚠️ **"새 배포"를 만들면 URL 이 바뀌어 팀 전원이 재설치**해야 한다. 반드시 기존 배포를 편집할 것.

## 적용 후 확인
1. 편집기에서 `testRead()` — 팀원 7명, 작업 수가 이전과 같은지
2. `testMemberList()` — 경고 없음
3. 앱에서 동기화 2~3회 — 콘솔 `[sync] ...ms` 가 두 번째부터 빨라져야 함
4. **완료 체크 → 바로 동기화** — 체크가 유지되는지 (4번 무효화 검증) ★가장 중요

## 되돌리기
캐시만 끄려면 `READ_CACHE_SEC` 를 `0` 으로. 1·2번(버그 수정·중복 제거)은 그대로 둬도 안전하다.
전체 롤백은 편집기의 **배포 관리 → 이전 버전**으로.
